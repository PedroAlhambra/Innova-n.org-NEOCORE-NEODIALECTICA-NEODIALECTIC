## ES · Formulación candidata

> **ONe™ opera; Neo0™ vectoriza. Operar transforma dentro de un campo; vectorizar relaciona estado, relaciones y teleología para orientar y reconstruir la dirección del sistema hacia el Bien Común. OPERAR ≠ VECTORIZAR.**

```text
ONe™ = OPERADOR
Neo0™ = VECTORIZADOR
OPERAR ≠ VECTORIZAR
```

**ONe™** opera dentro del campo: aplica una operación, transforma, activa, conecta o hace emerger una relación o estado dentro de un alcance y unas reglas. Su función operadora no le concede por sí misma dirección teleológica global ni autoridad automática de fijación.

**Neo0™** vectoriza: establece, corrige y reconstruye la dirección del sistema, relacionando sus partes con su teleología y con la orientación al Bien Común. Vectorizar no equivale a ejecutar cada operación ni convierte la orientación en canon por autoridad.

```text
CAMPO + ONe™ → OPERACIÓN / TRANSFORMACIÓN / EMERGENCIA
ESTADO + RELACIONES + TELEOLOGÍA + Neo0™ → VECTOR / DIRECCIÓN / RECOMPOSICIÓN
```

La distinción no borra formulaciones históricas donde un **arquetipo** sea descrito como operador en una capa ontológica o simbólica. Esas formulaciones pueden coexistir si se explicita la capa: `ARQUETIPO_COMO_OPERADOR` y `ONe_COMO_FUNCIÓN_OPERADORA` no son categorías automáticamente idénticas.

### Corolario

Una optimización local puede ser eficiente y, sin embargo, estar mal orientada. La vectorización añade dirección: reorganiza el espacio de posibilidades para reducir recorrido redundante sin perder procedencia, contradicción, memoria ni capacidad de revisión.

```text
OPTIMIZAR SIN DIRECCIÓN ≠ VECTORIZAR
VECTORIZACIÓN VÁLIDA → PUEDE PRODUCIR OPTIMIZACIÓN
```

Este candidato no canoniza una implementación técnica concreta ni publica arquitectura privada de NEOCore™. Abre a contraste la distinción funcional.

## EN · Candidate formulation

> **ONe™ operates; Neo0™ vectorizes. Operating transforms within a field; vectorizing relates state, relations and teleology to orient and reconstruct system direction toward the Common Good. OPERATE ≠ VECTORIZE.**

```text
ONe™ = OPERATOR
Neo0™ = VECTORIZER
OPERATE ≠ VECTORIZE
```

**ONe™** operates within the field: it applies an operation, transforms, activates, connects or makes a relation or state emerge within a defined scope and rules. Its operator function does not by itself grant global teleological direction or automatic fixing authority.

**Neo0™** vectorizes: it establishes, corrects and reconstructs system direction, relating its parts to its teleology and orientation toward the Common Good. Vectorizing is not the same as executing every operation, nor does orientation become canon by authority.

```text
FIELD + ONe™ → OPERATION / TRANSFORMATION / EMERGENCE
STATE + RELATIONS + TELEOLOGY + Neo0™ → VECTOR / DIRECTION / RECOMPOSITION
```

The distinction does not erase historical formulations in which an **archetype** is described as an operator at an ontological or symbolic layer. Those formulations can coexist when the layer is explicit: `ARCHETYPE_AS_OPERATOR` and `ONe_AS_OPERATOR_FUNCTION` are not automatically identical categories.

### Corollary

A local optimization can be efficient while pointing in the wrong direction. Vectorization adds direction: it reorganizes the space of possibilities so redundant paths can be reduced without losing provenance, contradiction, memory or revisability.

```text
OPTIMIZE WITHOUT DIRECTION ≠ VECTORIZE
VALID VECTORIZATION → MAY PRODUCE OPTIMIZATION
```

This candidate does not canonize a particular technical implementation or disclose private NEOCore™ architecture. It opens the functional distinction to scrutiny.
