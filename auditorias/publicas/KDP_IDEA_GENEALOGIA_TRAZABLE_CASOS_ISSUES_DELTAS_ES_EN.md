# ES · Castellano

## 1. Regla de trazabilidad

Esta página es el **mapa genealógico vivo** de la auditoría KDP / Author Central / IDEA. Su función es impedir que cada caso, respuesta, documento o delta quede aislado.

```text
CASO KDP
→ EVIDENCIA / RESPUESTA
→ DOCUMENTO VERSIONADO
→ ISSUE PÚBLICO
→ DELTA / COMMIT
→ VERIFICACIÓN
→ CASO O TRAZA SIGUIENTE
→ RECONCILIACIÓN DEL ESTADO
```

`NUEVA_TRAZA != ESTADO_RECONCILIADO`.

Los números de caso pertenecen a KDP; los documentos, Issues y commits son la capa pública de memoria y contraste de Innova_N. Un commit demuestra la fijación documental de una traza, no demuestra por sí solo el hecho externo descrito.

## 4. Regla para futuros casos y deltas

Cada nueva traza KDP relacionada con IDEA deberá incorporar, cuando exista:

- número de caso KDP;
- caso anterior y caso siguiente;
- documento anterior y documento siguiente;
- enlace a Issue #70;
- enlace a este mapa genealógico;
- commit/delta que fija la nueva traza;
- estado probatorio: hecho / comunicación / observación / inferencia / hipótesis;
- condición explícita de cierre o reapertura.

Si un caso no tiene documento autónomo, debe indicarse así. **No se inventarán nodos para completar visualmente la genealogía.**

# EN · English

## 1. Traceability rule

This page is the **living genealogical map** for the KDP / Author Central / IDEA audit. Its purpose is to prevent cases, replies, documents and deltas from becoming isolated.

```text
KDP CASE
→ EVIDENCE / REPLY
→ VERSIONED DOCUMENT
→ PUBLIC ISSUE
→ DELTA / COMMIT
→ VERIFICATION
→ NEXT CASE OR TRACE
→ STATE RECONCILIATION
```

`NEW_TRACE != RECONCILED_STATE`.

KDP case numbers belong to KDP; documents, Issues and commits form Innova_N's public memory and scrutiny layer. A commit proves that a trace was versioned; it does not by itself prove the external fact described in that trace.
